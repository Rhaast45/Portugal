// LOG_FILE_05 — DIAGNOSTIC & TROUBLESHOOTING

TROUBLESHOOTING PORTFOLIO

Scenario-based diagnostic protocols and resolution workflows for common IT, hardware, network, and system failures.

CASE 01 // Computer Cannot Connect to Wi-Fi Network
Problem Description
Workstation fails to associate with the wireless access point or displays "No Internet, Secured" / "Unable to connect to this network" while other devices operate normally.
Possible Causes
  • Wireless NIC / adapter disabled in Network Connections or Device Manager
  • Corrupted, outdated, or generic wireless NIC device driver
  • Incorrect static IP configuration or stale DHCP lease collision
  • Router / Access Point MAC address filtering, band steering, or DHCP pool exhaustion
  • DNS resolver failure or unreachable upstream DNS servers
Diagnostic Procedure
  1. Verify physical/software Wi-Fi switch and check ncpa.cpl to confirm wireless adapter is enabled.
  2. Execute ipconfig /all in CLI to inspect IPv4 configuration, default gateway, and DHCP status.
  3. Execute loopback ping (ping 127.0.0.1) to confirm TCP/IP stack integrity.
  4. Execute gateway ping (e.g. ping 192.168.1.1) and external IP ping (ping 8.8.8.8) to isolate internal vs external layer connectivity.
  5. Test name resolution using nslookup google.com to verify DNS operation.
Applied Solution
Reset TCP/IP stack and Winsock catalog via netsh int ip reset and netsh winsock reset. Flushed DNS resolver cache via ipconfig /flushdns and renewed lease via ipconfig /renew. Configured fallback reliable DNS (1.1.1.1 / 8.8.8.8) and updated wireless driver from vendor package. Verified full connectivity restoration.
Lesson Learned
Always follow the OSI model bottom-up (Physical → Data Link → Network → Transport). Isolating IP connectivity from DNS name resolution saves substantial diagnostic time in field support.
CASE 02 // Workstation Fails to POST / Black Screen on Power-Up
Problem Description
The workstation powers on, but shows no display and does not complete POST. Fans or lights may turn on, but there is no operating-system startup.
Possible Causes
  • Loose or faulty memory module, graphics card, or power connector
  • Display, cable, or monitor input issue mistaken for a POST failure
  • Incorrect or unstable firmware settings
  • Faulty power supply, motherboard, CPU, or other component
Diagnostic Procedure
  1. Confirm the monitor is powered on, set to the correct input, and connected to the active graphics output; test with a known-good cable or display if available.
  2. Power the workstation off, unplug it, and follow ESD precautions before checking internal components.
  3. Inspect motherboard POST LEDs or beep codes and reseat accessible power and display connections.
  4. Boot with only essential hardware; test one memory module at a time in the motherboard-recommended slot.
  5. If needed, reset firmware settings using the motherboard manufacturer's procedure. Test or replace a PSU only with appropriate equipment or qualified assistance; never open the PSU.
Resolution Approach
Use POST indicators and a minimal-hardware boot to isolate the failing component. Reseat or substitute only the component identified by testing, restore firmware defaults when appropriate, then reconnect devices one at a time and verify a normal POST.
Lesson Learned
Separate display-path problems from POST failures first. Change one variable at a time, follow component safety guidance, and avoid replacing parts based on symptoms alone.
CASE 03 // Chronic System Slowdown & 100% Disk Utilization
Problem Description
A Windows workstation responds slowly or freezes while Task Manager reports sustained 100% disk active time, even when reported read/write throughput is low.
Possible Causes
  • Storage device health problems, connection faults, or a saturated drive
  • Background updates, indexing, synchronization, or another process producing sustained I/O
  • Insufficient memory causing heavy paging
  • System-file issues or unwanted software consuming resources
Diagnostic Procedure
  1. Use Task Manager and Resource Monitor (resmon) to identify processes with sustained disk activity.
  2. Check storage-device health with the manufacturer's diagnostic utility or available SMART monitoring.
  3. Back up important files before running repair scans or extended tests, especially if the drive may be failing.
  4. Review Windows Update and system logs, check memory pressure, and run a Microsoft Defender scan as appropriate.
  5. If storage health is good, use Windows servicing tools such as DISM and sfc /scannow when system-file corruption is suspected.
Resolution Approach
Address the cause identified by monitoring rather than disabling services at random. If diagnostics indicate a failing drive, prioritize a verified backup and replace the drive; avoid stressing a failing disk with intensive scans. If the drive is healthy, resolve the identified background workload or system issue and recheck performance.
Lesson Learned
100% active time is a symptom, not a diagnosis. Check drive health and protect user data before running disk-intensive repair or benchmark tools.
CASE 04 // Network Office Printer Not Detected on Subnet
Problem Description
Workstations cannot discover or print to a shared network printer after a subnet change. The printer may be offline to clients, or jobs may remain queued.
Possible Causes
  • The printer's address or subnet settings changed, or clients use a stale address
  • Clients and printer are on different VLANs without the required routing or access rules
  • The Windows Print Spooler is stopped, or the queue or driver has a problem
  • Discovery is unavailable across the subnet, or a firewall rule blocks the configured print protocol
Diagnostic Procedure
  1. Confirm the printer's current IP address, subnet mask, gateway, and link status from its network menu or configuration page.
  2. Check the client's network configuration and test reachability; note that a failed ping alone does not prove the printer is offline.
  3. If available, open the printer's embedded web page and confirm its network status.
  4. Check the Print Spooler service and queue, then verify the printer port and installed manufacturer driver.
  5. Ask the network administrator to verify VLAN routing and narrowly scoped firewall rules for the configured print protocol.
Resolution Approach
Once the network path is confirmed, assign the printer a stable address through an approved DHCP reservation or network plan, update the client port to the current address, and use the supported vendor driver. Clear only the affected stale jobs and validate printing from a test workstation.
Lesson Learned
Separate name discovery, IP connectivity, and print-queue issues. Use an address managed by the network team and allow only the print services the environment actually needs.
CASE 05 // Corrupted Windows User Profile ("Signed in with a Temporary Profile")
Problem Description
Windows displays a temporary-profile warning at sign-in. The user's normal desktop, settings, and files may not appear in the current session and changes made there may not persist after sign-out.
Possible Causes
  • A profile hive or user-profile service error prevents the usual profile from loading
  • Insufficient disk space, file-system problems, or permissions prevent access to the profile directory
  • A pending update, security product, or other process interferes with profile loading
  • A mismatched or damaged profile mapping requires further investigation
Diagnostic Procedure
  1. Do not save important work in the temporary session; notify the user and arrange a safe backup of existing profile data.
  2. Check Event Viewer → Windows Logs → Application for User Profile Service errors around the sign-in time.
  3. Confirm the original profile directory exists, has expected data, and the system drive has sufficient free space.
  4. Check Windows updates, disk health, and relevant service or security-product errors before changing profile settings.
  5. Only if necessary, have an administrator back up the registry and verify the exact user SID and profile path before making any ProfileList changes.
Resolution Approach
After safeguarding the user's data and identifying the cause, follow the supported repair path for the specific profile error. If the original profile cannot be repaired safely, create a fresh profile and migrate the user's files and required settings from a verified backup. Avoid deleting or renaming registry keys without confirming the SID-to-profile mapping.
Lesson Learned
Treat the warning as a data-protection issue first. Preserve the original profile, avoid storing work in the temporary session, and back up registry data before any advanced repair.

// THREAT_ANALYSIS UNDERSTANDING SQL INJECTION (SQLi) VULNERABILITIES

What it is: SQL Injection (SQLi) is an injection attack where malicious SQL statements are inserted into entry fields (e.g., input forms, HTTP headers, query string parameters) for execution by the database backend. It remains consistently in the OWASP Top 10 vulnerabilities category.

How it happens: SQLi occurs when an application concatenates untrusted user input directly into dynamic database query strings instead of parsing code and data separately. This enables the attacker to manipulate the query logic, bypass authentication, and execute arbitrary commands.

Potential Risks & Impact: Unauthorized authentication bypass, full loss of confidentiality (exposure of sensitive records, hashed passwords, PII), database data tampering or deletion, administrative takeover, and lateral escalation to underlying server OS commands.

// DEFENSIVE MITIGATION STRATEGIES & ARCHITECTURAL CONTROLS

1. PREPARED STATEMENTS (PDO / Parameterization)

Separates query parsing from data execution at the database engine level, rendering malicious SQL strings inert.

2. INPUT VALIDATION & WHITELISTS

Validates data types, lengths, and formats strictly against expected formats before queries process.

3. PRINCIPLE OF LEAST PRIVILEGE

Application DB accounts must only possess specific SELECT, INSERT, UPDATE grants; strictly deny DROP, ALTER, and administrative roles.

4. MODERN ORM & WEB APPLICATION FIREWALL (WAF)

Deploy ORMs with built-in parameterization and back with Cloudflare/ModSecurity WAF inspection to filter malicious query payloads at edge.
